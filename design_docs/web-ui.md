# Web UI

Operator UI + marketing landing for the email_outreach system. Lives in
`src/web/`. Two audiences in one app, separated by route:

* `/` → marketing landing page (problem, how it works, who it's for, CTA)
* `/app/*` → operator UI (campaigns, companies, drafts, embedded observability)

The UI is fully self-contained: in dev, an in-browser MSW service worker
returns seed data, so the operator UI runs end-to-end with no backend. When
the gateway service is built, point `VITE_API_BASE_URL` at it (or run nginx in
front to proxy `/api/*`) and the same code hits the real backend.

## Develop

```bash
cd src/web
npm install
npm run dev          # http://localhost:5173 — MSW intercepts /api/*
```

Point at a real backend instead of the mock:

```bash
VITE_API_BASE_URL=http://localhost:8000 npm run dev
```

## Production container

```bash
docker compose up --build web        # http://localhost:8082
```

The container is multi-stage:

1. **node:20** builds the SPA to `/dist`.
2. **nginx:1.27-alpine** serves the static bundle and proxies `/api/*` to
   `$GATEWAY_URL` (default `http://gateway:8000`).

`nginx.conf` uses docker's embedded DNS plus a variable in `proxy_pass`, so
nginx starts even when the gateway service doesn't exist yet — requests to
`/api/*` return a clear `503 gateway_unreachable` JSON until it comes up.

Important: MSW is disabled in the production build (`import.meta.env.DEV` is
false). The mock only runs in `npm run dev`. So a prod container needs a real
gateway, or you'll see 503s on `/api/*`.

## API contract (what the gateway must implement)

Source of truth: `src/web/src/api/endpoints.ts`. Types in `src/web/src/api/types.ts`.

| Method + path | Returns | Used by |
| --- | --- | --- |
| `GET /api/campaigns` | `Campaign[]` | Campaigns list, Companies/Drafts lists (for filter) |
| `POST /api/campaigns` | `Campaign` | New-campaign dialog |
| `GET /api/campaigns/:id` | `Campaign` | Campaign detail |
| `GET /api/campaigns/:id/companies` | `CompanyDetail[]` | Campaign detail (Companies tab), Companies list |
| `GET /api/campaigns/:id/drafts` | `Draft[]` | Campaign detail (Drafts tab), Drafts list |
| `GET /api/campaigns/:id/timeline` | `TraceEvent[]` | Campaign detail (Timeline tab) |
| `GET /api/companies/:id` | `CompanyDetail` | Company detail |
| `GET /api/drafts/:id` | `Draft` | Draft detail |
| `PATCH /api/drafts/:id` | `Draft` | Draft detail (approve / reject / edit subject+body) |
| `POST /api/early-access` | `{ ok: true }` | Landing CTA |

Field shapes mirror the Python Pydantic / Beanie models in
`src/shared/models/`. Keep snake_case keys on the wire.

`Draft` mutations the operator UI sends:

```ts
PATCH /api/drafts/:id  Body: { status?: "draft_created" | "failed"; subject?: string; body?: string }
```

## Adding a new page

1. Create `src/pages/app/MyPage.tsx`.
2. Define the data fetch in `src/api/endpoints.ts`.
3. Add a route in `src/App.tsx`.
4. Add a sidebar item in `src/components/app/Sidebar.tsx`.
5. If you need new mocked data: extend `src/api/mocks/seed.ts` and add an MSW
   handler in `src/api/mocks/handlers.ts`.
